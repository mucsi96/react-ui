# Full component parity audit

## Reference and method

Audited every public component exported by `packages/ui/src/index.ts` against:

- Angular theme/gallery commit `e77a5093bcce775037abe80679c297545bca1fc1`.
- Cooking's last Angular client (`ee5828c`, theme 1.12.0) for its avatar,
  recipe typography, and chip treatment.
- React baseline `6b81e11` for the before screenshots.

Ran the Angular gallery locally, inspected computed styles and rendered states,
and compared it with the production React gallery. The React suite exercises
desktop and Pixel 7 layouts, keyboard/pointer actions, reduced motion, focus
restoration, validation, and WCAG 2/2.1 AA checks. Screenshots of the React before
and after builds accompany the PR; Angular screenshots are reference evidence,
not assertions that differently composed gallery pages are pixel-identical.

## Remaining differences — not claimed as pixel parity

1. **Accessible contrast:** Angular's #9ca3b0 labels on #384252 measure 4:1.
   React uses `--bt-text-muted-on-raised: #aab2bf` for filled field labels and
   placeholders so the existing AA checks pass. Error labels retain the softer
   readable error token. Text/outlined button labels retain neutral readable
   text instead of Angular's low-contrast primary blue.
2. **Framework interactions:** React Aria retains native disabled behavior,
   visible keyboard focus rings, outside-dismiss semantics and focus management.
   Angular's disabled-interactive provider and Material ripples are not copied.
   Consumer-supplied icons remain ordinary React children; the library does not
   force Angular's Material Symbols font onto them.
3. **Composition:** Dialog action positioning, table captions/pagination,
   notification stacking and semantic badge tones are React APIs. Angular
   templates supply their own composition. These are audited, not represented
   as identical DOM/screenshot equivalents.
4. **Animation:** Bar-loader keyframes match. Spinner/progress animations remain
   React implementations, with reduced-motion support. The donut keeps its
   responsive text sizing when constrained narrower than its configured size.
5. **Typography:** The React `Heading` size scale remains explicit. Angular's
   gallery `mat-display-*` aliases actually render at inherited 16px in this
   reference build; reproducing that gallery omission is not a typography API.
6. **Application layout:** Cooking's grid, hero, navigation icons and print rules
   still need the consumer integration listed in [angular-parity.md](angular-parity.md).

## Release/integration notes

This changes visual defaults across the library: consumers should review their
CSS overrides for fields, button heights, chip dimensions and card padding.
`appearance="outlined"` remains available. The library's optional reset must be
imported explicitly; the normal stylesheet still does not reset application
headings. No Cooking dependency is updated or library package published by this PR.
